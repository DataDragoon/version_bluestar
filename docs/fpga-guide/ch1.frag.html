Two things that are easy to confuse

who wrote a block, versus where it is wired in

Every module in this chapter can be described on two independent axes, and mixing them up is the fastest way to misread the design.

Axis one — who wrote the IP

Four suppliers contribute code, one directory each under hdl/fpga/ip/:

Nuand
nuand
The company that designs and sells the bladeRF. Their own VHDL — the datapath, the command UART, the timestamp tamers, the arbiter.
Altera
altera
The FPGA chip vendor (bought by Intel in 2015, spun back out as Altera in 2025). Stock library parts that ship with Quartus — PLLs, FIFOs, SPI and I/O controllers, and the NIOS II soft CPU itself.
Analog Devices
adi
Makes the AD9361 transceiver. Supplies axi_ad9361, the core that drives the LVDS link to their own chip.
OpenCores
opencores
A community open-source IP repository. The I²C master came from there; Nuand wrapped it for Avalon.

Axis two — where it is instantiated

Independently of who wrote it, a block sits in one of two places:

  • Inside the Qsys system. It is on the NIOS’s Avalon bus, gets a base address, and may get an IRQ. These are the modules the firmware can read and write.
  • Hand-instantiated in VHDL — in bladerf-hosted.vhd, rx.vhd or tx.vhd. These are wired directly to pins and to each other, and the NIOS cannot address them at all.

Where I got this wrong

An earlier version of this chapter badged some modules “qsys” alongside “nuand” and “altera”, as if all three were vendors. They are not. Qsys is a tool, not a supplier — it is Altera’s system builder that generates the interconnect. Saying a block is “Qsys” says nothing about who wrote it. The badges below now name the vendor only; the section a module appears in tells you where it is wired.

The cross product is real, not theoretical. command_uart is Nuand IP living inside Qsys; rffe_spi is Altera IP inside Qsys; fx3_gpif is Nuand IP outside it; and nios2 — the CPU this whole guide revolves around — is Altera IP, not Nuand’s.

How the fabric is organised

source of truth · bladerf-hosted.qip + bladerf.qip

The FPGA is not a flat pile of modules. It is three clock domains with carefully guarded crossings between them, and almost every block belongs unambiguously to one of them. Get the domains right and the module list explains itself.

The build manifest is authoritative: bladerf-hosted.qip lists exactly which files are compiled in. Anything not in it — and there are some notable absences — is not in your bitstream, whatever else exists in the tree.

Clocking, reset and domain crossing

the plumbing every other block depends on

system_pll
altera
Makes the 80 MHz system clock from the 38.4 MHz reference. Everything in the Qsys system runs on it.
fx3_pll
altera
Generates the FX3 GPIF clock domain used by the host-interface side.
clk_ctrl
altera
Clock-control primitive gating each PLL output; one instance per PLL.
pll_reset
nuand
Reset sequencer that holds a PLL down until it is stable and locked, then releases downstream logic.
reset_synchronizer
nuand
Asynchronous assert, synchronous de-assert. One per domain — pclk, sys, rx, tx.
synchronizer
nuand
Three-flop crossing for single bits. The most-instantiated block in the design — roughly twenty copies carry meta_en, packet_en, usb_speed, MIMO enables and trigger state between domains.
handshake
nuand
Request/acknowledge crossing for multi-bit buses, where a plain synchronizer would let different bits land on different cycles and tear the value. Five instances, all carrying a 64-bit timestamp out of the AD9361 sample domain: one into the FX3 GPIF domain (so fx3_gpif can judge whether a TX burst is still in the future), and four into the Nios 80 MHz domain — a snap and a current copy in each of the two timestamp tamers.
ps_sync
nuand
Power-supply synchronization — not phase-shift. Drives the switching regulators with an LFSR-hopped frequency list to spread their emissions away from the RF band.
set_clear_ff
nuand
Small set/clear flip-flop primitive used by the datapath control logic.

Host interface

the sample pipe to the FX3, entirely separate from the control path

fx3_gpif
nuand
The GPIF II state machine. Moves IQ samples between the FIFOs and the FX3 bus, and prepends or strips the 16-byte metadata header when metadata mode is on. Runs in the PCLK domain.
fx3_gpif_p
nuand
Package of types and constants for the above.
common_dcfifo
altera
The dual-clock FIFO primitive underneath all five FIFO wrappers — the actual sample-domain to PCLK-domain crossing.
rx_fifo / tx_fifo
altera
Sample FIFOs, 8192 samples each. RX is 64-bit in / 32-bit out; TX is 32-bit in / 64-bit out.
rx_meta_fifo / tx_meta_fifo
altera
Parallel 2048-word metadata FIFOs carrying the timestamps and flags that ride alongside each buffer.
lb_fifo
altera
512-sample loopback FIFO for digital TX→RX loopback without leaving the FPGA.

Sample datapath

rx.vhd and tx.vhd, both in the AD9361 sample clock domain

axi_ad9361
adi
Analog Devices' interface core. Owns the LVDS physical link to the AD9361 — deserialises RX at 4:1, serialises TX — and emits ad9361.clock, the sample clock that defines the whole third domain.
rx.vhd
nuand
The RX chain: takes ADC samples, pushes them into the FIFOs, and owns the RX timestamp reset.
tx.vhd
nuand
The TX chain: drains the FIFOs into DAC samples, handles burst timing against the TX timestamp.
fifo_writer
nuand
Inside rx.vhd. Writes samples into the RX FIFO and generates the metadata header — timestamp, flags, status — for each buffer.
fifo_reader
nuand
Inside tx.vhd. Reads the TX FIFO, interprets metadata, and releases bursts at their scheduled timestamps.
fifo_readwrite_p
nuand
Shared package defining the state machines and record types those two use.
signal_generator
nuand
Synthetic sample source inside rx.vhd — substitutes a known tone or ramp for real ADC data in test and loopback modes.
rx_packet_generator
nuand
Top-level synthetic packet source, used to exercise the RX path with no RF present.
trigger
nuand
Instanced once in each of rx.vhd and tx.vhd. A handful of gates: passes the sample stream only when armed and the shared trigger line fires, and one board designated master drives that line. This is how multiple bladeRFs start capture on the same edge.

The Qsys system

nios_system · 22 instances, all in the 80 MHz domain

Everything below is generated into a single nios_system component instantiated once at the top level. Base addresses and IRQ numbers are assigned by the build script, not hand-written.

nios2
altera
The CPU — a Nios II/e ("Tiny") soft core at 80 MHz. Runs the packet dispatch loop that executes every host command.
ram
altera
On-chip memory holding the NIOS firmware's code and data; also its reset and exception vector target.
system_clock
altera
The clock source object defining the single 80 MHz domain the whole system shares.
command_uart
nuand
Receives 16-byte host command packets at 4 Mbaud from the FX3's UART, filters them against a magic-byte whitelist in hardware, and raises IRQ 7. Base 0x9120.
rffe_spi
altera
SPI master to the AD9361, 40 MHz. Every register write that tunes the radio goes through here. Base 0x9200.
peripheral_spi
altera
A second, slower SPI master (8 MHz) shared between the VCTCXO trim DAC and the ADF4002, demultiplexed in the fabric by a GPIO bit. Base 0x9060.
gpio_rffe_0
altera
32-bit PIO carrying the RF front-end control lines: the SPDT band switches, bias enables, TXNRX, MIMO enables, AD9361 reset. Base 0x9440.
control
altera
32-bit general control PIO. Carries meta_sync, the bit that gates metadata mode and therefore the timestamp counters. Base 0x9040.
rx_tamer / tx_tamer
nuand
The sample timestamp counters, one per direction, plus a compare register that raises an interrupt at a chosen sample. Counter runs in the sample domain; the register interface is here. Bases 0x9160 / 0x9140.
rx_trigger_ctl / tx_trigger_ctl
altera
8-bit PIOs arming and reporting the multi-board trigger described above.
xb_gpio / xb_gpio_dir
altera
32-bit PIO pair — data and direction — for the expansion-board header.
opencores_i2c
opencores
I²C master reaching the on-board sensors and EEPROM. Base 0x90f0.
arbiter_0
nuand
Two-requester bus arbiter guarding SPI access. In the hosted image the second requester is unconnected, so the NIOS always wins — but the firmware still pays a lock/poll/unlock around every SPI transaction.
wishbone_master_0
nuand
Avalon-MM to Wishbone bridge, exported to the top level. Base 0x10000000.
jtag_uart
altera
Debug console over JTAG, IRQ 1. Base 0x9100.
vctcxo_tamer_0
altera
Despite the name, on this board it is instantiated as a plain on-chip memory block, not the Nuand tamer IP — a register window the firmware reads. The actual VCTCXO disciplining state machine runs in NIOS software. Base 0x9300.
cb_ad9361_0_data
rb_ad9361_0_data
altera
Clock bridge and reset bridge letting Qsys reason about the AD9361 sample domain as a distinct clock.

What is not in this image

present in the source tree, absent from the hosted bitstream

Worth knowing, because searching the repo will find these and it is easy to assume they are running.

rfic_spi_controller
nuand
A hardware SPI state machine for the AD9361. Not instantiated in any Qsys system. The hosted image uses Altera's altera_avalon_spi instead, with the SPI frame assembled in NIOS software. It appears only in the WLAN image.
lms6_spi_controller
nuand
For the LMS6002D on the original bladeRF. Irrelevant to this board.
tone_generator
nuand
Added to the Qsys system only under a conditional branch of the build script; not in the default hosted build.
vctcxo_tamer (IP)
nuand
The real tamer IP exists, but as noted above the micro substitutes a memory block for it.

Consequence for the radar

Because there is no hardware SPI sequencer and no fabric-level retune logic, every frequency change on this board is software — NIOS firmware writing AD9361 registers one transaction at a time. The FPGA contributes only the timestamp compare that says when, and the pins that carry the bits.
