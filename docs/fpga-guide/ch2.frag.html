Chapter 02

The round trip

One sample, all the way out and all the way back: from a USB bulk transfer, across three clock domains, out of the antenna, and home again. Every module it touches, every wire it rides, and the cycle counts wherever the RTL commits to one.

The map

outbound above, inbound below, clock domains as vertical bands

The two directions are near-mirror images, and they share exactly one resource: the 32-bit GPIF bus, which is bidirectional and therefore half-duplex. Everything else is duplicated.

Outbound — USB to the antenna

1

The host hands over a buffer

EP 0x01 OUT · bulk · 512 B (HS) / 1024 B (SS) packets

Samples and control travel on completely separate endpoints — control is 0x02/0x82, samples are 0x01/0x81. The FX3 firmware sets up two AUTO DMA channels and then never touches sample data again: the USB producer socket feeds PIB_SOCKET_3 outbound, and PIB_SOCKET_0 feeds the USB consumer inbound. DMA buffers are packet_size × 8 — 4096 bytes on High Speed, 8192 on SuperSpeed — eleven deep.

libbladeRF enforces the match from its end: every buffer you configure must be a whole multiple of 8192 bytes, or it silently rounds up and warns.

2

Across the GPIF bus

fx3_pclk (in) · fx3_gpif[31:0] (inout) · fx3_ctl[12:0] (inout)

The FX3 is the clock master. The timing constraint sets the pin at 100 MHz; the firmware programs the PIB clock as SYS_CLK/4, which on the SDK default would be 96 MHz. The SDK is not in the repo, so the real figure sits somewhere between those two.

The control bus is asymmetric in a way worth remembering: bits 0–3 are FPGA outputs (the DMA acknowledgements), 4–12 are inputs (enables, idle, and four active-low DMA requests). Bit 9 is unusable because it carries DCLK, which is why the RX-1 request was relocated to bit 12. Only two of the four DMA channels are ever used — the FPGA always acknowledges on RX0 and TX3, so two of the four ack lines are permanently zero.

A transaction moves exactly one DMA buffer and then returns to idle. One 32-bit bus word is one SC16Q11 sample.

Total 2065 cycles for 8192 bytes — roughly 99% bus efficiency. The metadata lives inside the 2048-word buffer rather than on top of it, so enabling it costs four samples and zero extra cycles.

Two behaviours matter for a radar sweep. Arbitration favours TX: RX only pre-empts once its FIFO passes a critical watermark, deliberately, to avoid discontinuities in the transmitted signal. And because the bus is one set of wires, every direction change costs a dead gap — 13 cycles RX→TX, 16 cycles TX→RX.

3

Out of the FIFO, into the DAC

tx_sample_fifo 32→64, 8192 deep · tx_meta_fifo 32→128 · both show-ahead

fifo_reader runs two independent state machines on tx_clock. The meta FSM walks META_LOAD → META_WAIT → META_DOWNCOUNT; the sample FSM walks COMPUTE_ENABLED_CHANNELS → COMPUTE_OFFSETS → READ_SAMPLES. Those first two sample states are one cycle each and exist purely to recompute the channel packing whenever the FIFO runs dry.

Only two fields of the 16-byte header are ever parsed by the FPGA: the 64-bit timestamp, and in packet mode the length. The flags word — BURST_START, BURST_END, TX_NOW — is never read by any RTL; those are host-side bookkeeping. TX_NOW is encoded in the timestamp instead: the host writes zero, the reader subtracts one, it wraps to all-ones, and the comparison short-circuits.

The 64-bit read word unpacks with the sign-extension bits discarded — the FPGA re-derives sign from bit 11:

Bits63:6059:4847:4443:3231:2827:1615:1211:0
FielddiscardQ1discardI1discardQ0discardI0

With both channels enabled that is one FIFO read per sample instant — 1022 reads per 2044-word message, exactly matching the meta FSM downcount. With one channel enabled, a single read serves two consecutive samples.

From the release comparison going true it is 2 tx_clock cycles to data_v, 3 to the AD9361 data register. The −1 baked into the timestamp comparison exists precisely to pay for that pipeline.

Idle does not mean zero

When the FIFO runs dry, when a burst is not yet due, when the trigger is armed but unfired, or when tx_enable drops — data_v goes low and the DAC register simply holds its last value. It does not flush to zero. That is why libbladeRF zero-pads the tail of every burst in software, and why the metadata contract requires the last samples of a discontinuity to be (0+0j).

One more surprise here: the multi-board trigger does not gate samples at all. It forges the FIFO’s empty flag, so armed-but-unfired makes the reader believe the FIFO is permanently dry. A side effect is that an armed, unfired TX lights the underflow LED continuously. Once it fires, samples flow immediately at whatever the current time is, because the burst’s scheduled timestamp was already consumed while waiting.

The crossing

8 LVDS pairs each way · 6 data lanes, frame, clock

This is the one part of the chain the FPGA does not define. The AD9361 is always in 2R2T LVDS mode on this board, so the framing never changes regardless of how many channels you enable.

The clock chain follows from that geometry: DATA_CLK = 4 × fs, and the factor-4 DDR deserializer halves it, so l_clk = 2 × fs. At a 10 Msps sweep that is a 40 MHz link clock and a 20 MHz fabric clock. The TX side has no clock of its own — it is regenerated from the RX pin through a shared PLL, so the AD9361’s DATA_CLK is the single clock source for the entire radio datapath.

Frame lock is self-checking: every 4-slot frame nibble must be the bitwise inverse of the previous one, which holds only if the period is exactly 8 UI. That check drives the core’s status bit.

One detail that cancels out but will confuse anyone reading registers: the AD9361 has I/Q swap enabled on both ports, so what the RTL calls “I” is the part’s Q. Deliberate, and symmetric end to end.

Inbound — antenna to USB

4

Through the ADI core

ad9361_adc_{i0,q0,i1,q1} · each carries enable, valid, data[15:0]

Twelve l_clk cycles of countable pipeline sit between the deserializer and the fabric: frame decode, 48-bit assembly, data formatting, DC filter, IQ correction. All four channels are bit-identical, so there is zero relative skew between I and Q or between channels. Channel 0 trails channel 1 by one cycle, because it waits in the assembly register for its partner.

valid arrives once every two l_clk cycles — the same rate whether one channel or two is enabled. What changes is how many streams carry payload on it.

The enable line is a trap: it is a static configuration register bit, not a per-cycle data qualifier. It means “this channel is configured”, and the fabric treats it that way. The 12-bit sample arrives sign-extended and right-justified in 16 bits — note the asymmetry with TX, which is left-justified.

5

Packed into the FIFO

adc_streams / adc_controls → rx_mux → fifo_writer → rx_sample_fifo 64→32

rx_mux is the single register in the RX sample path, and it is where test sources substitute: a 12-bit ramp, a 32-bit counter, or the digital loopback FIFO fed from TX. All are explicit host commands; nothing switches automatically. The trigger gate is applied only in normal mode — counter and loopback modes bypass it entirely.

fifo_writer packs by shifting 32 bits into the top of a 64-bit word for each enabled channel, so a MIMO pair fills one word in a single call:

Mode63:4847:3231:1615:0
ch0 + ch1Q1I1Q0I0
one channelQ (newer)I (newer)Q (older)I (older)

From a valid at the fabric boundary to the word resident in the FIFO is 4 rx_clock edges. The write cadence is one word every 2 cycles in MIMO, every 4 with a single channel — and either way 1022 writes per message, mirroring the TX side exactly.

6

The metadata header

128-bit word · emitted least-significant dword first · 4 bus words

The header is recomputed combinationally every cycle from the live timestamp and registered on every edge, so whichever cycle the meta FSM chooses to write, the value is current. On the wire it reads: magic 0x12344321, timestamp low, timestamp high, flags — the timestamp little-endian across two words, flags last.

The timestamp itself is a free-running divide-by-two of rx_clock, so it increments once per sample period and is never gated on data. It is held in reset whenever metadata mode is off.

There is no RX overrun status bit

The FPGA detects the condition — and then only blinks LED3. The overflow counter output is left unconnected in rx.vhd and synthesized away. The host infers overrun purely from a discontinuity in the header timestamps, which means without the metadata format there is no overrun detection at all. The underrun bit that does appear in the RX header is a TX condition, patched in on the way out — so you need an RX stream running to observe TX underruns.

7

Home

SETUP_RD 3 · META_READ 1 · SAMPLE_READ 2044 · FINISHED 11

The return transaction is five cycles shorter than the outbound one — 2060 against 2065 — because the RX acknowledgement can be asserted later. The FIFOs are show-ahead, so the head word is already presented and no read-latency bubble is needed; header and payload run contiguously with no gap at the boundary.

Then back out through PIB_SOCKET_0, into the USB consumer socket, and up EP 0x81 to the host.

One discrepancy I could not resolve

The RX cadence is firmly established — a strobe every two l_clk cycles, cross-checked against the testbench’s own timestamp assertions. The TX side should mirror it, same framing and same clock, but the DAC rate register is programmed to DAC_RATE(3) in 2R2T LVDS mode, which makes the ADI core request data every four cycles, not two.

I could not reconcile those from source. The AD9361 clock-tree code that would settle it lives in an unfetched submodule. Practically it does not threaten correctness — the FPGA logic is rate-agnostic, emitting exactly one sample per request and reading one 64-bit word per two samples whatever the ratio — but the absolute TX sample rate is not something this repo can confirm. Comparing the TX and RX timestamp rates on hardware would settle it in a minute.
