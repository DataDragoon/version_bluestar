What it is

the RX sample packer · between the RX mux and the RX FIFO

Chapter 5 covered the RX FIFO as storage. fifo_writer is what decides what goes into it and when. It takes the per-channel sample streams coming out of the RX mux, packs them into 64-bit words, and builds the metadata header that rides alongside.

It runs entirely in the rx_clock domain — the AD9361 sample clock — and contains two independent state machines coupled by a single interlock bit.

The width assertion inside passes with zero margin: 64 ≥ 2 channels × 2 components × 16 bits. There is no spare room in the write word.

One input worth noting: it is wired to mux_streams, not the raw ADC. So everything below applies equally to the counter and digital-loopback test modes — they go through the same packer.

Two state machines, one interlock

the sample FSM writes data; the meta FSM writes headers; neither runs alone

The interlock bit is meta_written. Samples must not enter the FIFO until the 128-bit header for the current message has been committed — otherwise the host would receive payload with no timestamp to label it. It is set when the header write actually happens, and cleared whenever the credit check fails. It is checked in exactly one place, at the top of the procedure that decides every write:

if( ((meta_current.meta_written = '1') or (meta_en = '0')) ) then
    ...  -- accumulate, pack, assert fifo_write
else
    fifo_future.fifo_write <= '0';
end if;

So with metadata enabled, no sample can enter the RX FIFO before the header that describes it. The ordering is structural, not a race the host has to tolerate. Chapter 5 noted that the metadata FIFO shares the RX FIFO's clear line specifically so the two cannot desynchronize; this is the other half of that guarantee.

Why the header waits for a sample

META_WRITE does not commit immediately. It waits for the first valid sample on any channel, then writes. That is deliberate: the header is built combinationally from the live counter every cycle, so committing it at the instant of the first sample makes the timestamp be that sample's timestamp, with no bookkeeping.

The two exit thresholds

META_DOWNCOUNT leaves at dma_downcount ≤ 2 — not zero. The reason is that samples keep flowing during the two cycles the FSM spends passing through IDLE and META_WRITE, because writes are gated on meta_written (still set) rather than on the meta FSM's state.

With one channel enabled, one write slips through that gap — 2 DWORDs. Threshold 2. But with both channels enabled a write happens on every valid cycle, so two writes slip through — 4 DWORDs. Hence the separate MIMO override that exits one write earlier, at ≤ 4. Get this wrong and every header lands off the message boundary.

The override is a bolted-on branch, and its comment admits as much:

-- Patches the late meta write for MIMO mode
if( in_sample_controls'length = 2 and
    in_sample_controls(0).enable = '1' and
    in_sample_controls(1).enable = '1' and
    eight_bit_mode_en = '0' and
    meta_current.dma_downcount <= NUM_STREAMS + 2 ) then
    meta_future.state <= IDLE;
end if;

Note how narrowly it is guarded: two streams, both enabled, and not eight-bit mode. It is written for exactly the configuration this board runs in, and steps over the ordinary ≤ 2 exit that the downcounter's stride of two can otherwise skip past.

How samples get packed

a right-shifting register with insertion at the top

Chapter 6 defines the three formats — SC16_Q11, 8-bit and SC12Q11 — and their bit layouts. This is the other half: how the accumulator that produces them actually fills.

All three packing modes work the same way: shift the accumulator right by one slot, insert the new sample at the top, once per enabled-and-valid channel. Since channel 0 is processed first, channel 1 ends up above it. The three pack functions differ only in the slot width they shift by — 32 bits for SC16_Q11, 16 for eight-bit, 24 for SC12Q11 — which is why one loop body serves all three.

Mode63:4847:3231:1615:0
SC16_Q11, 2 chQ1I1Q0I0
SC16_Q11, 1 chQ0 newerI0 newerQ0 olderI0 older

In both cases the older or lower-numbered data occupies bits 31:0 — which is exactly what the 32-bit FIFO read side emits first. The ordering is not arbitrary; it is what makes the host see samples in sequence.

The write cadence

One counter governs everything: samples_left = NUM_STREAMS − enabled_channels.

  • Two channels → 2 − 2 = 0 → a write on every valid cycle.
  • One channel → 2 − 1 = 1 → one valid decrements, the next writes → a write every second valid cycle.

8-bit mode halves it again via an alternating delay bit, since only 16 bits per sample instant are stored. The packed 12-bit mode is stranger still: it accumulates into a separate 96-bit buffer and emits a sliding 64-bit window across it, writing on three cycles out of every four — eight IQ pairs become three 64-bit words with no waste.

Two inconsistencies in the source

The 16-bit and 8-bit packers read the registered copies of the input; the 12-bit packer reads the raw ports, running one cycle ahead. It works out because the window select reads the pre-insertion buffer, but it is fragile and unlike its siblings.

And if 8-bit and packed-12-bit were ever enabled together, the data path and the control path would pick different modes — the override orderings are reversed between them. Nothing in the HDL prevents it; it relies on the NIOS never setting both.

The header it builds

128 bits, recomputed every cycle, committed once per message

BitsWidthContent
127:11612constant 0xFFF
115:1142constant "11"
113:1122mini-expansion pin state, synchronized
111:9616placeholder — overwritten downstream
95:3264timestamp
31:032magic 0x12344321

The header is rebuilt combinationally every cycle from the live counter and re-registered, so whichever cycle the FSM chooses to commit, the timestamp is current. No latching, no staleness.

The placeholder gets replaced on the way out. The GPIF interface overwrites bits 111:96 of the final word with the TX underrun flags — which is how a transmit-side problem reaches the host on a device with no reverse channel. Bits 127:112 pass through untouched.

The mini-expansion bits

Two external digital pins are sampled through 3-flop synchronizers and stamped into every header, giving the host a per-message snapshot of them, time-stamped by the same header. They surface as MINIEXP1 and MINIEXP2 in the host's flags word.

Worth knowing: mini_exp1 is the same physical pin as the multi-board trigger line. So MINIEXP1 in your metadata is effectively a per-buffer record of the trigger state.

The credit check — and why it does nothing in your build

fifo_enough

Two terms, both re-registered before use:

if( fifo_full = '0' and
    ((FIFO_MAX - fifo_used_v_r) > dma_buf_size) and
    ( (meta_en = '1' and meta_fifo_full = '0'
        and (META_MAX - 4) > meta_fifo_used_v_r)
      or (meta_en = '0') ) ) then
    fifo_enough <= true;

With FIFO_MAX = 8192 and a SuperSpeed dma_buf_size of 2048, the sample term trips at 6144 of 8192; the metadata term reserves 4 of 2048 header slots on top. The same signal is exported as packet_ready, so in packet mode the generator upstream sees the identical credit.

The reader has no counterpart to any of this. Its condition for popping is one word being present — no watermark, no headroom, no lookahead, and Chapter 6's fifo_usedw wired in and never read. TX flow control does not live in that module at all; it lives in fx3_gpif, which refuses to start a transfer above 6144 words (Chapter 4). RX flow control lives here.

Why the guard sits at a different end in each direction

The two directions fail differently. TX fails by running dry, which the FX3 side can prevent by keeping the FIFO topped up — a decision only the side holding the host buffers can make. RX fails by overrunning, which no upstream can prevent, because the ADC does not stop. So the only place a receive guard can work is immediately in front of the memory, and that is exactly where it is.

The flags are deliberately re-registered because the FIFO's outputs are unregistered and feed a wide subtract-and-compare. That costs staleness: counting the occupancy delay, the register stage, and the clocked comparison, the decision is about 3 cycles behind reality. The generous headroom absorbs it easily.

In plain SC16_Q11 mode, this check never throttles anything

The sample FSM leaves WRITE_SAMPLES on fifo_full or a missing header. With meta_en = '0' — the SFCW configuration — the second term is always false, so the only backpressure is the FIFO going genuinely full.

The writer therefore fills the FIFO completely, overflows, and only then holds off. fifo_enough degrades to pure recovery hysteresis: it decides when HOLDOFF may release, not when writing should stop. With metadata on, writes stop before the FIFO fills. Without it, they stop after.

There is also a genuine unit mismatch in that first term: the occupancy is counted in 64-bit words while dma_buf_size is in 32-bit DWORDs. The check therefore demands roughly twice the headroom it means to — 16 KiB reserved for an 8 KiB message. Conservative in the safe direction, and it costs a quarter of the buffer.

Overflow, and what is dead

the detector, and a fair amount of logic that goes nowhere

Overflow is flagged when four things coincide: the block is enabled, a valid sample is present, the FIFO reports full, and the writer is not clearing. A rising-edge detector then counts contiguous runs as one event.

if( enable = '1' and in_samples(in_samples'low).data_v = '1' and
    fifo_full = '1' and fifo_current.fifo_clear = '0' ) then

Unlike the reader's underflow detector, which fires on a condition rather than a collision, this one requires valid data actually arriving at a full FIFO. But it examines only stream 0's valid. In every rx_mux mode the mux drives data_v for all streams from a common source, so on this board stream 0 pulses whenever stream 1 does. Whether that remains true when the host enables channel 1 alone depends on how the ADI core drives its channel-0 valid, which is in the unfetched no-OS submodule and cannot be settled from this checkout.

The LED is off during the overflow

This module and fifo_reader end with the same three processes — detect, count, hold an LED — and the counters are byte-for-byte equivalent. The one-shots are not. The difference is a single keyword:

overflow_led <= '0';
if( overflow_detected = '1' ) then
    downcount := to_integer(overflow_duration);
elsif( downcount /= 0 ) then
    downcount := downcount - 1;
    overflow_led <= '1';
end if;

Chapter 6 shows the reader's version, where the reload is a separate if and the decrement runs regardless. Here the reload is the taken branch, so while overflow_detected is high every cycle the decrement never executes and overflow_led never rises.

What that means at the front panel

A sustained TX underflow lights its LED and holds it. A sustained RX overflow leaves its LED dark — it comes on only once the overflow stops, then holds for 65535 clocks. The RX LED reports that an overflow ended, not that one is happening. Chapter 2's finding that the FPGA exposes no RX overrun status bit is the other half of this: the LED is the only fabric-level indication there is, and it is off for the duration of the event.

The writer generates a FIFO-clear signal and the instantiation simply omits the port. The register survives only because an internal consumer reads the record field. The FIFO's real flush comes from a different domain entirely — the inverted RX enable, in PCLK. The writer's own clear capability is unused.
Packet states
inert
Two of the four states in each FSM exist only for packet mode, which this build never enables. One of them, WRITE_PACKET_PAYLOAD, also has no exit other than a full disable — dropping packet mode mid-stream would wedge the FSM.
The header keeps building
waste
Even with metadata off, the 128-bit header register is recomputed and re-latched every single cycle; only the write strobe is suppressed. And since the timestamp counter is held in reset in that mode, what it latches is zeros.

Two hazards worth recording

HOLDOFF freezes the 12-bit packing phase but not the sample accumulator or its counter. In the single-channel case, an odd number of samples shifting through during a holdoff would swap which sample lands in the high versus low half of the word on resume. Derived from the source; not observed.

And the credit check's subtraction can wrap for one cycle as the full flag deasserts, briefly asserting fifo_enough while the FIFO is still nearly full. A one-cycle window that the full flag immediately closes.
