What it is

32-bit in, 64-bit out, 8192 words deep

One M10K-backed dual-clock FIFO, 32 KiB of storage, sitting between the FX3 bus and the AD9361 sample clock. Written 32 bits at a time by the GPIF interface, read 64 bits at a time by the sample reader.

The wrapper is a pure pass-through to Altera's dcfifo_mixed_widths; every generic is forwarded verbatim. Three of them shape everything downstream:

  • LPM_SHOWAHEAD = "ON" — the head word is already present on q. rdreq is an acknowledge, not a request. This is why the reader never waits a cycle for data.
  • ADD_USEDW_MSB_BIT = "OFF" — neither occupancy counter can express “completely full”; both wrap to zero. That is why the separate full flags exist, and why the RX side concatenates full & usedw before comparing.
  • OVERFLOW_CHECKING / UNDERFLOW_CHECKING = "ON" — the megafunction internally masks wrreq when full and rdreq when empty. This is the only cycle-level protection the TX write side has.

The depth is not set where you would expect. The wrapper defaults to 4096 and is overridden at instantiation to 2**(sample_fifo.wused'length) — the width of the record field, which is itself derived from TX_FIFO_LENGTH = 8192. So the single knob is TX_FIFO_LENGTH; editing the wrapper default alone does nothing.

What has to be true for a write

wrreq is asserted in exactly one state

wrreq defaults low every cycle and is set in one place only — the SAMPLE_WRITE state of the GPIF state machine. Getting there requires, in order:

  • The FX3 asserts its TX-enable line and raises a DMA request on one of the TX request pins.
  • The watermark passes: fewer than 6144 of 8192 words occupied, and the metadata FIFO below half full. Either term failing blocks the transfer before it starts.
  • Arbitration in IDLE picks TX — which it normally does, since TX is checked before a non-critical RX to avoid discontinuities in the transmitted signal.
  • If metadata is on, the header's timestamp survives a check: zero (send now) or more than 32 ticks in the future. A late buffer is discarded entirely — the FSM diverts to SAMPLE_WRITE_IGNORE, raises the underrun flag, and wrreq is never asserted for those 2048 words.

Note what is not in that list: the full flag. Once a burst starts, wrreq is unconditional for its whole length. The 2048-word headroom the watermark guarantees is the entire safety margin, backed only by the megafunction's internal masking.

And for a read

rdreq needs all of these simultaneously: the trigger-gated empty is low; the metadata FSM has reached the scheduled launch timestamp; loopback back-pressure is clear; at least one enabled DAC channel is asking for a sample; and the MIMO unpacker has exhausted the current 64-bit word. With two channels enabled that last condition is met on every request; with one channel, every other request.

The trigger is wired into the empty flag

the least obvious thing in this chapter

The FIFO's rdempty output does not go to the reader. It goes to a signal named sample_fifo_rempty_untriggered, passes through the multi-board trigger block, and only its output reaches fifo_reader:

txtrig : entity work.trigger(async)
    generic map ( DEFAULT_OUTPUT => '1' )
    port map (
        signal_in  => sample_fifo_rempty_untriggered,
        signal_out => sample_fifo.rempty
    );

Inside, it is three lines of combinational logic. While the trigger is armed and has not fired, rempty is forced high — the reader believes the FIFO is permanently dry while data keeps accumulating behind it. That is how a triggered transmit holds without touching the FIFO's real state.

Two consequences

An armed-but-unfired TX lights the underflow LED continuously, because the underflow detector also watches this gated flag. And the metadata FIFO's empty flag is not gated this way — it goes straight through. If you assume the two FIFOs behave symmetrically here, you will be wrong.

Wired but never read

signals that cost routing and do nothing

wrfull, wrempty
dead
Both are routed from the FIFO, through tx.vhd, across the entity boundary into fx3_gpif — where each appears exactly once, in its own port declaration. Four signals crossing two boundaries to be discarded. The RX side does read its full flag, so this is a TX-only oversight, not a convention.
rdfull
dead
Connected to a record field that appears once in the whole file — the port map line itself. Driven, never read, never leaves the module.
rdusedw
dead
Wired into fifo_reader, but the body never references the value. Only its 'length is used — to size the very port that goes unread. fifo_reader is driven purely by the empty flag.
underflow_count
open
Explicitly left open. A 64-bit counter is synthesized and observed by nothing; only the LED one-shot escapes.
READ_THROTTLE state
dead
The throttle generic is 0, which makes the guard statically false — an entire FSM branch is unreachable in this instance.
Half of every record
note
The tx_fifo_t record describes one FIFO's whole interface, but the design splits that FIFO across two files. Each file leaves the other's half at its default, so roughly half of every declared record instance is constant-folded away. Nothing breaks; it just means the record is a naming convention, not a bundle.

Where the data comes from

one 32-bit word, tracked

Before it arrives:

host app → libbladeRF → USB 3.0 bulk OUT → FX3 GPIF II
  → fx3_gpif[31:0] pins → register_gpif (1 pclk reg)
  → fx3_gpif.gpif_mux (1 more pclk reg) → tx_fifo

After it leaves:

tx_fifo → CDC to tx_clock → fifo_reader (unpack + timestamp gate)
  → dac_assignment_proc (truncate to 12 bits, left-justified)
  → axi_ad9361 → LVDS → AD9361 DAC → TX1 / TX2

The metadata rides a parallel track for part of that journey only. It enters fx3_gpif, is shifted into a 128-bit buffer, dribbles into the meta FIFO during the sample writes rather than before them, and is consumed by the reader's metadata FSM — where it never becomes samples. It only decides when the sample FSM is allowed to pop.
